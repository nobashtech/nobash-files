# Security Policy

Nobash Files performs sensitive operations on website files. Use staging for changes and maintain separate, tested, off-site backups.

## Reporting a vulnerability

**Do not open a public GitHub issue containing exploit details or sensitive data.** Contact the maintainers privately using the security contact listed on [nobash.com](https://nobash.com/) and verify the destination before sharing confidential information. Provide the affected version, a minimal reproduction, potential impact, and suggested mitigation if available.

## Scope and support

- Use supported WordPress and PHP versions listed in the README.
- The project has **not** received an independent penetration-test certification.
- Security fixes and support timelines are not guaranteed; assess risk and isolate access to trusted administrators.
- Never share live credentials, private recovery files, or customer data in a public issue.
